# FitFace 퍼스널 컬러 12유형 고정 계획

작성일: 2026-06-13
상태: 계획 확정, 구현 대기 (가상착장 Phase 0과 같은 날 진행 예정)

## 0. 배경 — 현재 문제

퍼스널 컬러 진단의 `type` 필드가 **자유 문자열**이다.

- 프록시 JSON 스키마가 `'type': {'type': 'string'}`으로만 제약 (enum 없음).
- 모델이 "여름 쿨", "쿨 서머", "여름 쿨 라이트" 등 어떤 표기든 반환할 수 있어
  재진단 시 표기가 흔들린다.
- rule-based 폴백은 자체 6유형(봄 웜/가을 웜/여름 쿨/겨울 쿨/뉴트럴 브라이트/
  뉴트럴 소프트) 고정이라 AI 경로와 유형 체계가 다르다.
- 이 type 문자열이 프로필에 저장되고 AI 판단 프롬프트(스냅샷/비교)와
  가상착장 프롬프트에 주입되므로, 표기 불일치가 후속 기능 일관성까지 흔든다.

## 1. 결정 사항

**A안 채택: 유형만 enum으로 고정, 팔레트/코멘트는 AI 자유 생성.**

- 판단 주체는 여전히 AI 모델이다. 답안 형식만 객관식으로 바꾼다
  (주관식 → 12개 보기 중 선택).
- 추천/주의 색상과 코멘트는 사진에 맞춰 모델이 개인화 생성한다
  (B안 — 팔레트까지 고정 — 은 AI 역할이 분류기로 줄어들어 기각).

## 2. 고정 유형 목록 — 12계절 체계

조사 근거: 12계절 체계는 1980년대 4계절 분석(Color Me Beautiful)을
명도/채도 축으로 세분화한 국제 표준 확장이며, 한국 시장에서도 12타입이
통용 표준이다. 분류 축은 온도(웜/쿨) × 명도(라이트/딥) × 채도(브라이트/뮤트).

| # | 유형 (저장 문자열) | 계절 | 특징 축 |
|---|---|---|---|
| 1 | 봄 웜 라이트 | 봄 | 웜 + 고명도 + 부드러움 |
| 2 | 봄 웜 트루 | 봄 | 웜 중심 |
| 3 | 봄 웜 브라이트 | 봄 | 웜 + 고채도 |
| 4 | 여름 쿨 라이트 | 여름 | 쿨 + 고명도 |
| 5 | 여름 쿨 트루 | 여름 | 쿨 중심 |
| 6 | 여름 쿨 뮤트 | 여름 | 쿨 + 저채도 |
| 7 | 가을 웜 뮤트 | 가을 | 웜 + 저채도 |
| 8 | 가을 웜 트루 | 가을 | 웜 중심 + 저명도 |
| 9 | 가을 웜 딥 | 가을 | 웜 + 저명도 |
| 10 | 겨울 쿨 브라이트 | 겨울 | 쿨 + 고채도 |
| 11 | 겨울 쿨 트루 | 겨울 | 쿨 중심 + 저명도 |
| 12 | 겨울 쿨 딥 | 겨울 | 쿨 + 저명도 |

16타입 확장은 보류한다. 앱의 판단 근거(저해상도 비전 + 색 통계)로는
12타입 분해능이 상한이고, 12가 시장 통용 어휘로 충분하다.

## 3. 작업 항목

1. **프록시 JSON 스키마에 enum 추가** — `_personalColorSchema`의 `type` 필드를
   위 12개 문자열 enum으로 제약. structured output이라 모델이 목록 밖
   값을 반환할 수 없게 된다.
2. **프롬프트에 판정 기준 명시** — `PersonalColorPromptBuilder`에 12유형
   목록과 판정 축(웜/쿨 × 명도 × 채도) 기준표를 추가해 판단 근거를 고정.
3. **rule-based 폴백을 12유형으로 정렬** — 기존 6유형 분기를 12유형 매핑으로
   확장. 앱이 이미 계산하는 `warmCoolBias`(온도), `brightness`(명도),
   `saturation`(채도)이 분류 축과 1:1 대응하므로 임계값 분기 확장으로 가능.
   - 뉴트럴(웜/쿨 경향 미약) 처리: 12계절 체계에는 뉴트럴이 없으므로
     명도/채도 값으로 가장 가까운 계절에 배정한다. 구체 규칙은 구현 시 결정.
4. **Local Gemma 경로 검증 추가** — 로컬 모델은 스키마 강제가 안 되므로
   프롬프트에 12유형 목록 명시 + 응답 파싱 후 목록 밖 값이면 가장 유사한
   유형으로 매핑(또는 rule-based 폴백).
5. **기존 저장값 호환** — 이미 저장된 "여름 쿨" 등 옛 표기는 그대로 표시하고,
   새 진단부터 12유형을 적용한다. 마이그레이션 강제 변환은 하지 않는다.
6. **테스트** — 프록시 스키마 enum 검증, rule-based 12유형 분기,
   Gemma 응답 목록 밖 값 매핑.

## 4. 영향 범위

- `lib/openai_proxy/openai_proxy_server.dart` (스키마)
- `lib/domain/services/personal_color_prompt_builder.dart` (프롬프트)
- `lib/domain/services/rule_based_personal_color_service.dart` (폴백 + 유형별 팔레트 12종)
- `lib/domain/services/local_gemma_personal_color_service.dart` 또는 파싱 계층 (검증/매핑)
- 가상착장 계획(VIRTUAL_TRYON_PLAN.md)의 프롬프트 주입은 변경 불필요 —
  `personalColorPromptLine()`이 type 문자열을 그대로 쓰므로 자동으로 일관성 향상.

## 5. 미결정 사항

- 뉴트럴 → 계절 배정의 구체 임계값 규칙
- rule-based 12유형별 고정 팔레트 색상 구성 (구현 시 작성)
